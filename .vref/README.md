# iOS Visual Reference

A browsable gallery of the app's committed snapshot baselines, for design review
and store-asset prep. It is not a visual regression suite — that is
`make verify` and `make e2e-simulator`, which pixel-compare the same images.

The gallery is **local-only today** — build it with `make vref` and view it with
`make vref-serve`. Publishing it at `ios.put.io/vref/` is separate, future work
tracked in [#49](https://github.com/putdotio/putio-ios/issues/49).

## What is committed, and what is not

`manifest.json` and this README are committed. `screenshots/` and `index.html`
are gitignored and regenerated by `make vref` from the baselines under
`PutioUITests/__Snapshots__/` and `PutioTests/__Snapshots__/`.

That split is deliberate. The baselines are the single source of truth — CI
pixel-compares them — so copying them into git twice would let the copies drift
from what is actually asserted. Regenerating takes about a second and needs no
simulator.

Because the copies are absent in a clean checkout, all three commands below
regenerate them first, so any of them works immediately after cloning.

## Commands

```sh
make vref            # copy baselines, refresh the manifest, write index.html
make vref-serve      # the above, then serve on 127.0.0.1:4173
make vref-validate   # regenerate, then check the manifest and every asset
```

## Editing the manifest

`make vref` rewrites only the mechanical fields — `file`, `group`, `platform`,
`device`, `viewport`, `sizeBytes`, `capturedAt`, and the top-level `updatedAt`.
Curated text is yours:

- `title` — what the screen is called
- `tags` — used by the filter rows
- `notes` — what a reviewer should look at

`capturedAt` comes from the baseline's last commit **author** date rather than its
mtime, so a fresh checkout does not dirty the manifest. Author date rather than
committer date specifically because rebasing rewrites the latter, and a stacked
branch gets restacked often — using it would churn every entry for reasons that
have nothing to do with the images.

Adding or removing a baseline is a deliberate step: a baseline with no manifest
entry fails the sync rather than being added with a placeholder title, and a
manifest entry with no baseline fails too. Both messages name the id.

## Rules

The gallery is published publicly, so everything here must be public-safe.

- The images come from `PUTIO_E2E_MOCK_API` fixtures, never a real account. Keep
  it that way: no real usernames, file names, content ids, tokens, or local IPs.
- Baselines are recorded with the licensed brand faces bundled, so the gallery
  shows real typography. Run `make fonts-setup` before recording.
- The app is dark-only, so every capture is dark mode.
- Screens are captured on a pinned iPhone 17 Pro Max (1320x2868); components
  render directly in unit tests at their own sizes.

Nothing here is published yet, but keep to the rule anyway: once #49 lands, a
**removed or renamed** screenshot can persist at its old URL until the bucket is
purged. Treat public-safe content as the control, not after-the-fact deletion —
the same warning `putio-roku` carries.
